# telegram-api

Доступ к своему аккаунту Telegram через MTProto (Telethon). Bot API тут не годится —
бот видит только адресованные ему сообщения.

## Настройка

1. my.telegram.org → API development tools → получить `api_id` и `api_hash`.
2. `cp .env.example .env` и вписать их (файл в .gitignore).
3. Если подключение падает с `TimeoutError` — Telegram недоступен напрямую,
   впиши в `.env` `TG_PROXY` (SOCKS5/HTTP или ссылка MTProxy, примеры в `.env.example`).
4. `uv run tg.py login --qr` — QR в терминале, сканировать телефоном
   (Настройки → Устройства → Подключить устройство). Код из приложения
   сторонним клиентам Telegram иногда молча не доставляет, QR от этого не зависит.
   Без `--qr` — вход по коду: `uv run tg.py login` — номер телефона, код из Telegram, пароль 2FA если есть.

Создастся `sessions/personal.session` — это полноценная авторизованная сессия,
видна в Telegram → Настройки → Устройства. Хранить как пароль, в git не класть.

## Команды

    uv run tg.py chats -n 30          # список диалогов с id
    uv run tg.py send Петя привет     # сообщение: '@user', +телефон, id или имя из диалогов
    uv run tg.py send '@user' -f a.pdf подпись   # с файлом
    uv run tg.py send --dry-run Петя  # только показать, кому уйдёт
    uv run tg.py search php           # публичные каналы и группы по названию/@username
    uv run tg.py resolve @a @b        # проверить @username: тип, подписчики, описание
    uv run tg.py activity @a @b       # живой чат или накрученный
    uv run tg.py find @chat Пенза     # упоминания слова внутри чата
    uv run tg.py media <чат> -n 50    # аудио и голосовые: VOICE / audio, длительность, mime
    uv run tg.py get <чат> <msg_id>   # скачать в downloads/ и разобрать
    uv run tg.py probe <файл>         # разбор уже скачанного файла

`<чат>` — id из `chats` или @username. В PowerShell `@user` бери в кавычки:
без них `@` — это splatting, и аргумент молча пропадает.

`send` по имени ищет подстроку среди диалогов; если подходит несколько —
ничего не отправляет, а печатает список, чтобы уточнить.

`search` ищет только по публичным названиям и @username, выдача урезана сервером
(десяток результатов). Полного каталога каналов в API нет. Поэтому связка: список
каналов набирается где угодно — веб-подборки, каталоги вроде tgstat — а `resolve`
проверяет их через Telegram: жив ли канал, канал это или чат, сколько подписчиков.
Цифры отдаёт только сам Telegram, в подборках они обычно устаревшие.

`activity` отделяет живое от накрученного: число подписчиков ничего не значит,
смотреть надо, сколько людей реально пишет за месяц. Группа на 8000 подписчиков
с нулём сообщений за 100 дней — накрутка; группа на 500 с сотней активных —
настоящая. `find` ищет слово внутри чата: так проверяется, есть ли в
мультигородском чате реальные люди из нужного города или город приписан
в заголовок ради поисковой выдачи.

## MCP-сервер

`mcp_server.py` даёт то же самое Claude Code и другим MCP-клиентам — в любой
сессии можно сказать «найди чат с Костей» или «напиши ему, что опоздаю».

    claude mcp add --scope user telegram -- uv run --script <путь>/mcp_server.py

Инструменты: `search_chats` (по подстроке в имени или @username), `read_messages`,
`send_message`, `send_file`. Сессия общая с CLI, сначала `tg.py login`.
Клиент подключается на каждый вызов и сразу отключается: sqlite-сессия
заблокирована, пока клиент держит соединение, и CLI параллельно бы не работал.

Отправка идёт с личного аккаунта и не отменяется — в описании инструментов
модели велено отправлять только после подтверждения получателя и текста,
а Claude Code и так спрашивает разрешение на вызов.

## Что показывает разбор

`media` печатает флаг из API: `VOICE` — сообщение отправлено как голосовое
(`DocumentAttributeAudio.voice=True`), `audio` — как аудиофайл. Это различие точное.

`probe` проверяет, похож ли файл на честную запись с микрофона: кодек, моно/стерео,
битрейт, теги энкодера. Признаки косвенные — через `sendVoice` как голосовое можно
отправить любой заранее подготовленный файл, и на уровне протокола он не отличается.
